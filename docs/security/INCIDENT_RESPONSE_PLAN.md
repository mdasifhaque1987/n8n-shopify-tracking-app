# Security Incident Response Plan

## Scope

This plan applies to suspected unauthorized access, disclosure, alteration, loss or unavailability of protected customer data, credentials, production systems or encrypted backups.

## Response stages

1. **Identify and triage**
   - Record the detection time, affected system and initial evidence.
   - Assign severity and an incident owner.
   - Avoid copying protected data into tickets or chat messages.

2. **Contain**
   - Disable affected credentials, integrations or services.
   - Restrict access and isolate affected systems.
   - Preserve relevant audit and system logs.

3. **Eradicate**
   - Remove malicious access or vulnerable components.
   - Rotate affected Shopify, platform, database and encryption credentials.
   - Patch and validate the affected application.

4. **Recover**
   - Restore from a verified encrypted backup when required.
   - Validate data integrity, application behavior and monitoring.
   - Re-enable service gradually.

5. **Notify**
   - Notify affected merchants, Shopify and regulators when required by contract or applicable law.
   - Provide confirmed facts, affected periods, mitigation steps and recommended merchant actions.

6. **Post-incident review**
   - Complete a written root-cause review.
   - Track corrective actions to completion.
   - Update controls, policies and training.

## Testing

The plan is reviewed annually and after material infrastructure or processing changes. A tabletop exercise is documented at least annually.
